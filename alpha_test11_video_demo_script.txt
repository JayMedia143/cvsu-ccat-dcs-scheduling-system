Good day! Today, I will show you the complete page-by-page flow of our CvSU Scheduling System. This walkthrough covers all the features of our desktop web application. Let us begin at the Login Portal. This portal has a built-in security rate limit. If someone enters the wrong password five times, their account is locked, and they are banned from logging in for fifteen minutes. This protects the system from unauthorized access. Now, let us enter our correct admin credentials and click the login button. The system redirects us directly to the Dashboard.

Now we are inside the Dashboard. On this page, you can see four metrics cards: eighty-seven courses, forty-three sections, twenty-nine faculty members, and seventeen rooms. 

To manage our curriculum data, click on the Data dropdown menu in the top menu bar. First, select the Courses page. Here you can see a grid of all subjects. Each course shows its code, description, lecture hours, and lab hours. Next, open the Sections page from the Data dropdown. This page shows a table of all student groups, their year levels, course tracks, student counts, and active curriculum years. Next, click on the Students page, which shows a table of all enrolled students. After that, select the Irregular Students page. This contains the Irregular Pathfinder tool, which checks for schedule conflicts for irregular students who have unique subject combinations. Next, click on the Faculty page. This page lists all teachers. Clicking a teacher opens their profile, where we can set their maximum teaching hours and their availability preferences, allowing us to block out times when they are busy. Next, open the Rooms page. Here we list all classrooms. Each room is set as a standard Lecture room or a specialized Laboratory. The system enforces these room types to ensure laboratory classes are only scheduled in lab rooms. We then visit the Departments page to manage academic departments. Finally, select the Pre-assignments page. Here we can add locked schedules by selecting a specific Course, Faculty, Room, Day, and Time range for one or multiple Student Sections at the same time. The algorithm will keep these locked slots and build the rest of the schedule around them.

Once all data is set, navigate to the Scheduling dropdown menu in the top menu bar. Select the first option, which is the Constraints page. On this page, we can configure the rules of our algorithm. We can toggle specific rules on or off, and adjust their penalty weights using sliders. Hard constraints represent critical conflicts—like double-booking a teacher or overloading a student section—which must be completely resolved. Soft constraints represent user preferences—like minimizing student class gaps or preventing teachers from teaching late nights—which we want to minimize but are not absolute blockers. Next, select the Auto-Schedule Generator page. Here, we choose the Semester, the Active Draft Version, and which Campus Departments to schedule. There is also a Fresh Start checkbox to erase the old schedule of the semester before starting. When we click, the system runs a mandatory Capacity Assessment. This Pre-Feasibility check compares our total session hours against our physical room capacities across three levels: Raw, Realistic, and Buffered. If there are not enough physical rooms, the system lists the overflow subjects that will be placed in TBA rooms. Once we click continue, the AI solver starts. We see a real-time canvas showing red slots for conflicts, blue slots for locked pre-assignments, and green slots for safe placements. We also see a Calculation Thread panel. This panel shows our active conflicts, generations per second, real-time logs, and the Hardware Mode. The system profiles the server's CPU cores and memory, since the algorithm runs on the server when deployed. If the server has a fast multi-core processor, it scales up to a larger population of two hundred schedules. If the server is low-end, it scales down to fifty schedules to prevent overloading the server. You can also click the minimize button to let the generator run in the background while you navigate other pages. Once resolved, the Victory popup appears, and we click view schedule.

To check classroom capacity safety, open the Check Conflicts page from the Scheduling dropdown. This is our Pre-Feasibility Check page. It checks total required course hours against the total available classroom hours. If we require five hundred class hours but only have classrooms for three hundred hours, the page alerts us immediately with color-coded warning cards: Green means perfect room capacity, Yellow and Orange warn of tight space, and Red alerts us that the schedule is mathematically impossible. This prevents administrators from running the generator on an impossible layout. We can also view the Pending Sections, Pending Faculty, and Pending Room pages from the Scheduling dropdown to see queues of resources that are still waiting for assignment. Finally, open the Schedule Editor page in the Scheduling dropdown. This is our interactive drag-and-drop timetable grid. Admins can view schedules sorted by sections or rooms. If you need to make manual edits, you can simply click, drag, and drop any class box to another time slot. Let us demonstrate how our real-time conflict auditor works. If I drag a class box and try to drop it into a slot where the instructor is already busy in another classroom, the target slot highlights in Red and a warning popup details the conflict. The system blocks the move to prevent manual errors. However, if we drag the class to a free slot, the target highlights in Green, and the system saves the change to our database instantly.

Next in our top menu bar, click on the Chats tab. This opens our collaborative Proposal Hub. Here, deans can submit change proposals directly. Before the super-administrator approves any request, our system runs an automated conflict analysis on the proposal. For example, if a dean proposes moving a class to Room 102 on Wednesday afternoons, the system checks if the room and teacher are completely free. If verified as safe, it displays a Green confirmation. We click the Approve button, and the master calendar updates instantly without the need for endless coordination emails.

Moving to the next tab, click on the Layouts link in the top menu bar. This page allows us to customize our scheduling grids. We can choose between different timeline layouts, toggle grid headers, adjust slot heights, and customize our colors. Following this, click on the View link in the top menu bar to open the View Timetable page. Here, we can filter our finalized schedules by student section, individual professor, or specific rooms to view clean grids. Next, we open the Reports link in the top menu bar. It allows us to generate printable schedules and export them as PDF documents. These files can be printed or shared directly in student and faculty groups.

To see the student experience, we will log out and navigate to the Portal dropdown menu, selecting Open Student Portal. This page is a dedicated search portal designed specifically for students. It requires no login credentials. Students simply select their course, year level, and section from the dropdown menus and click search. The system displays a read-only timetable of their weekly classes, showing them exactly when and where they need to report.

Now, let us log back in as an administrator to explore our account settings and security configurations. We click on our User Icon on the right side of the top menu bar. This opens our profile settings dropdown. Inside this dropdown, we can click the Change Username option to update our display name, the Change Password option to update our password, or the Upload Picture option to change our profile image. Next, we click on the Users dropdown menu in the top menu bar. We select the first option, which is the User Management page. On this page, we see a database of all registered system accounts. We can add new users, edit their profile details, or change their security roles—assigning them as Superadmin, Admin, or Standard User to restrict their access to specific departments. Next, we click on the User Monitoring page under the Users dropdown. For our system administrators, this page serves as an active security audit log, displaying login histories, timestamps, IP addresses, and recent admin actions. We can also click the User Registration page to quickly sign up new deans and staff members.

Next, we click on our User Icon dropdown once more and scroll down to the Recycle Bin. If an administrator deletes a course, student section, faculty member, or room, the record is not permanently erased immediately. Instead, it is sent to the Recycle Bin. In this dropdown menu, we can access the Courses bin, Sections bin, Students bin, Faculty bin, Rooms bin, Schedules bin, Code Rules bin, Departments bin, or Users bin. This allows us to inspect deleted records and either click the restore button to return them to the active lists, or permanently purge them to keep our active database clean.

Finally, we click on our User Icon dropdown and select the Manage Archives page to view our Previous Semesters portal. In the Archives portal, we can finalize and archive our active term's schedule. This saves the entire semester's data as a read-only historical archive. We can then clear out the active database to start a fresh semester with a clean slate. If we ever need to review previous schedules, we can open the Previous Semesters dropdown in the top menu bar and select any past archive. The system loads that semester's data in a read-only view, allowing us to inspect historical classes, rooms, and faculty schedules. Once finished, we can simply exit the archive mode and return to our active term. In conclusion, the CvSU Scheduling System is a complete, highly organized, and completely sequential partner for our campus administration. Thank you for watching!
