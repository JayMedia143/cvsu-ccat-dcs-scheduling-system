Listen closely as I explain Test 3! Compared to Test 2, we added a very important step: the Pre-Feasibility Check! In Box 1, we start execution. Boxes 2 to 4 handle the loading of data and parsing of pre-assignments. Notice that parsing pre-assignments is part of initialization, not the check itself! Then, in Box 5, we run check_room_feasibility. This is much better than Test 2 because it prevents the algorithm from wasting time on data that cannot possibly fit! In Box 6, we check the feasibility result. In Box 7, we apply the HC-24 Filter. Boxes 8 to 13 handle the genome creation and random placement. In Box 14, we start the loop. Box 15 calculates fitness, and Box 16 uses the Bitmask Caching Scan we introduced in Test 2! Boxes 17 to 21 handle the constraint checking and sorting. In Box 22, we check if conflicts are zero. If yes, we return the schedule in Box 24. If not, we run the genetic operators in Boxes 25 to 35, which are standard operations. This Test 3 is a big improvement over Test 2 because of the early feasibility check!
